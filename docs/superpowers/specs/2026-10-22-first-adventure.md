# First Connected Adventure

## Intent and authorization

Turn the accepted pixel courtyard into a small complete browser action RPG adventure. The user accepted the proposed camp → forked road → monastery route, groups of monsters including a spirit, a ritual objective/reward, and light skin/hair/sash customization, then explicitly asked the team to implement while they are away. The coordinator makes routine design and art acceptance decisions; this is not a claim that the user personally reviewed each asset.

Target a first exploratory playthrough of roughly 5–10 minutes. This is a pacing target to assess in play, not a promise or a reason to add waiting. Preserve the existing monk combat, dimensional 2:1 isometry, readable pixel art and compact stone HUD. Desktop keyboard/mouse remains the target.

## Playable scope

- Three distinct connected spaces: a safe amber-lit camp, a larger broken road with a genuine optional fork, and a monastery court containing the ritual source. Transitions work in both directions and retain cleared enemies, shrine use, and discovery state during the run.
- Several separated encounters rather than one crowd at spawn. Hounds close and leap; wraiths drift, visibly aim, then release an avoidable ranged shot. Damage must not pass through solid scenery. Entry positions are safe from immediate unavoidable attacks.
- A side route offers a one-time secret cache and restorative shrine. The cache is optional; skipping it never blocks the main objective.
- Quest: leave camp, reach the monastery, defeat its guardians, destroy the exposed ritual source with combat, return to camp and claim one amber bead. The bead is a trophy for this run; no invented persistent inventory or stat bonus. Claiming it ends the adventure with a clear summary.
- The ritual is visibly sealed while guardians remain, vulnerable afterwards, and destroyed once. Defeat/restart resets the whole run. Pause freezes combat, projectiles, transitions and visible action time.
- Character creation is part of the existing welcome panel, not a new screen: three skin tones, shaved/short hair, and three sash colors. Preview changes immediately and the choice is visible on the actual hero throughout the run, including back views and animations. Restart preserves the chosen appearance. No account or remote save.
- A single interact key, E, handles nearby transitions, cache and camp reward. Show a contextual prompt and map markers; E must never trigger several interactions on one press. Existing WASD/arrows, LMB, Q/RMB, Space, Esc and M remain.

## Technical and visual constraints

Use the installed Babylon.js/Vite/JavaScript stack and node:test. No new dependencies, publishing, Git initialization, changes to AGENTS.md, or modification of accepted Paper boards/concept originals. Work in the existing directory with exclusive file ownership. Immutable baseline: `/private/tmp/night-ritual-pre-adventure-20261022`.

32 native pixels per world unit; fixed orthographic 2:1 view; nearest filtering and no mipmaps for sprites; binary actor alpha; consistent feet anchors. Wraith uses real distinct front/back poses and mirrored side facings, with idle4/drift6/attack6/hurt4/death6 keys per authored facing. Actor cells are 96×96, anchor [48,84], maximum 48 opaque colors per family. Derive art from the accepted wraith originals in `assets/concepts/animation-bible-01/monsters/`. Record sources, exact generation prompts, normalization and validation. Preserve existing v2 packages. Appearance variants keep the same frame/clip ordering and feet anchors as the v2 monk, with a maximum of 48 opaque colors per variant.

Camp, road and court must have recognizably different composition and accents while sharing existing stone material language. Use existing world/floor assets and code-native geometry where appropriate, keeping walkable routes clearly distinguishable. Do not present temporary colored boxes as final character artwork.

## Shared integration contract

The gameplay owner owns the following APIs and data. Other owners consume them; a needed contract change goes through the coordinator and is recorded.

- Preserve `createGame()` as the existing single-court simulation fixture for regression tests. Add `createAdventure(appearance = {})` in `src/game.js` for the actual application. Existing `updateGame`, `startAttack`, `startDash`, `startWave` work with both. Add `interact(game)` returning a boolean and `getInteractionPrompt(game)` returning a string, plus `getObjective(game)` returning `{title, copy}`.
- `game.world` is the current location record (absent only in the legacy fixture): `{id, title, subtitle, tiles, pillars, braziers, obstacles, spawn, shrine, exit, portals, secret, ritual}`. Points use `{x,y}`. Optional points can be null. `portals` contain `{id,x,y,target,label}`. World geometry stays separate from mutable run state.
- Generalize `hasTile`, `isWalkable`, `moveBody`, `findPath`, `clearLine` with an optional final world argument, preserving existing defaults. Export immutable `LOCATIONS` from `src/campaign.js` with keys `camp`, `road`, `courtyard`. Layout coordinates and composition are the gameplay owner's call; write the module early for the renderer owner to consume.
- `game.locationId`, `game.locationRevision` (increments on every transition), `game.appearance` and `game.adventure` exist in adventure mode. `game.adventure` contains `quest` (`outbound|ritual|return|complete`), `secretFound`, `rewardCollected`, `visited` (array of ids), `totalKills`, and `elapsed`. The gameplay owner may add internal state; these public fields stay stable.
- `game.enemies` is only the current location's bodies with unique stable `id`, `kind` (`hound|wraith|ritual`) and the existing position/hp/state/direction/timer fields. Dead bodies remain until transition. Ritual is an inert damageable body, sealed while living guardians remain. `game.kills` counts killed current-location monsters (not the ritual). `game.shrineUsed` refers to the current location. `game.projectiles` contains `{id,x,y,dx,dy,radius,life}` for live wraith shots.
- Wraith uses states `idle|chase|windup|recover|stunned|dead`, with 0.8s locked-direction windup, 0.6s recovery, and one non-homing shot per windup. Gameplay owns tuning of hp, speed, ranges and shot damage. Export its timing constants from `src/campaign.js` if renderer needs them. Transition clears projectiles, pending attacks/dash and effects so old actions cannot cross into a new location.
- `Renderer` keeps its existing constructor/render contract, rebuilds and disposes location-specific objects when `locationRevision` changes, and snaps its camera safely on entry. A same-length enemy list is not sufficient to identify a location. Legacy tests and projection/picking remain valid. Use masks for wraith picking and correct height for projectiles/ground telegraphs.
- Art package `assets/game/pixel-v3/wraith/manifest.json` exports `wraith` with the v2 atlas metadata shape, clips named `idle`, `run` (drift), `attack`, `hurt`, `death`; matching `wraith.png` and `hit-masks.json` keyed by `wraith.png`. Renderer owns registration and loading.
- Appearance package `assets/game/pixel-v3/appearance/manifest.json` exports `{skins:[{id,label}],hair:[{id,label}],sashes:[{id,label}],default:{skin,hair,sash},variants:[{id,skin,hair,sash,path,previewPath}]}`. IDs are `warm|deep|pale`, `shaved|short`, `wine|teal|ochre`, default warm/shaved/wine. 18 prebuilt monk atlas PNGs and single-frame preview PNGs live beside the manifest. Metadata is inherited from v2 monk. Variants preserve the exact alpha mask so existing frame masks remain correct; short hair stays within the head silhouette. `id` is `${skin}-${hair}-${sash}`. UI owns `src/appearance.js` with `normalizeAppearance(value)`, `appearanceVariant(value)` and `appearanceOptions` using this manifest; `appearanceVariant` returns absolute runtime URLs as `url` and `previewUrl` alongside its metadata. Renderer imports these helpers, loads the selected atlas before showing it, and never changes gameplay state to apply a look.
- Main/UI owns E routing, notices for `transition`, `secret`, `ritual-open`, `ritual-destroyed`, `reward` events, current objective/location, appropriately sized monster progress, and reward/defeat summaries. Gameplay can add event details but preserves existing events for audio and presentation.

## Acceptance

Meaningful deterministic tests cover transition eligibility/state persistence, secret/reward once, ritual lock/unlock/destruction, death and restart, ranged attack telegraph/collision/invulnerability, and appearance validation. Preserve existing combat, projection and animation regression tests. Asset checks cover all atlas frames, ordering, colors, alpha, stable anchors and matching preview selections. Run the full test suite and production build after integration.

Coordinator plays the complete route in Chrome: chooses a nondefault look, visits secret, fights both enemy kinds, destroys ritual, returns and claims reward; also checks defeat/restart, paused projectile/action and backtracking. Inspect 1440×900, 1024×768 and 800×600 CSS layouts. Save tab-only screenshots and real observations. A fresh independent reviewer checks the final patch against the baseline and targeted failures; unresolved material findings block completion. State measured pacing and limitations honestly.
