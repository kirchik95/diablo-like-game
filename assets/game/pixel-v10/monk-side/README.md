# Monk side view — pixel package v10

Side-view (screen-right) idle and run for the monk. Running or aiming straight left or right no longer shows the SE/NE drawing turned 26.6° off the run direction. The screen-left view is the horizontal mirror.

## Files

- `monk-side.png`: RGBA atlas, 960×1056, 10 columns × 11 rows, cell 96×96, anchor `[48, 84]`, 110 keys. Rows 0–9 are `pixel-v2/monk/monk-v2.png` byte for byte. Row 10 holds the ten side keys. Binary alpha, transparent RGB is zero.
- `appearance/<skin>-<hair>-<sash>.png`: the same layout for all 18 appearances. Rows 0–9 are the shipped `pixel-v3/appearance/<id>.png` byte for byte. `warm-shaved-wine.png` equals `monk-side.png`.
- `manifest.json`: schema 2, the v2 monk contract plus `rows: 11`, `clips.idle.side` (100–103) and `clips.run.side` (104–109). `logicalFacings` adds `E` (authored side) and `W` (side, `flipX`). `appearance.variants` lists the 18 atlas paths.
- `hit-masks.json`: `{ "monk-side.png": { width, height, bits } }`, little-bit-first packed alpha. Alpha is identical for every appearance.
- `source/rig.json`: generated rig record per side key: source upper-body frame and offset, hip, knee, ankle, foot pitch, and the measured ground contacts.
- `previews/`: `compare-3x.png` and `compare-run.gif` (existing SE run beside the new E and W run), `side-4x.png`, `run-side.gif`, `idle-side.gif`, `run-track.gif` (the run crossing the floor at 18 px per key), `foot-track-3x.png` (planted-sole guides), `all-looks-2x.png`, `index.html` (player over the exact atlas pixels; open from disk).
- `provenance.json`, `qa-report.json`: generated by the builder.

## Contract

| Clip | Keys | Front (SE) | Back (NE) | Side (E) |
|---|---|---|---|---|
| idle | 4 | 0–3 | 50–53 | 100–103 |
| run | 6 | 4–9 | 54–59 | 104–109 |
| attack1–3, dash, wave, hurt, death | — | v2 | v2 | none |

- Native density 32 px per world unit, the same as v2. Hero height: idle 59–61 px, run 53–61 px (v2 idle 62, run 52–63).
- Run keys advance with travel, `.56u` per key (`MONK_RUN_KEY_DISTANCE`). Screen-horizontal travel moves 32 px/u, so the planted sole must move back 18 px per key in the cell. It does exactly:
  - keys 1–2: the near (right) foot stands flat on the same ground pixels; key 3 pushes off on the toe tip of that footprint;
  - keys 4–6: the same for the far (left) foot;
  - foot contacts land on keys 1 and 4, like the v2 run, so footstep audio stays in sync.
- One step is 54 px (1.69u); the cycle is 108 px.

## How the keys were made

No image generation. `scripts/build-monk-side-animation.py` builds a cut-out rig:

1. Upper body (head, torso, arms, beads, sash) is an exact v2 drawing: run keys 1–6 (atlas 4–9) for the run, the attack1 recovery guard (atlas 14) for the idle. The old trousers and feet are removed; the drawing moves so its waist sits on the rig hip.
2. Lower body (seat, legs, feet) is drawn in profile from joint positions: two-bone legs (thigh 14, shin 14.5 px), baggy tapered capsules, upper-left light, the v2 trouser and skin ramps, a 1 px ink rim. The far leg is one ramp step darker.
3. Idle breathing: the hip moves 0/−1/0/+1 px and the hanging sash ends sway 1 px.
4. Appearances: each variant copies the upper body from its own v3 atlas cell (its skin, sash and registered hair), and draws the legs with the same v3 seven-step skin map. Non-target materials are identical across variants.

The profile run phases follow `assets/concepts/pixel-art-01/raw/p8-pixel-run-and-hit.png` (contact, compression, push). That concept is a reference only; no pixels are sampled from it.

## Commands

```sh
python3 scripts/build-monk-side-animation.py                # rebuild the package
python3 scripts/build-monk-side-animation.py --verify-only  # rebuild in memory, compare bytes and hashes, validate; no writes
```

Requirements: Python 3.10+, Pillow ≥10, <13.

## Runtime

`src/pixel-animation.js` adds a side band: headings within 20° of screen-horizontal (entered inside 15°, left beyond 25°). Only clips with a `side` entry use it. `src/pixel-assets.js` declares this 110-key atlas as the shared monk geometry, and `src/appearance.js` maps every appearance to `appearance/<id>.png`. The v3 folder still provides the small appearance previews.
