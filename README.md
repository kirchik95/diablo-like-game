# Ночной ритуал

Играбельный прототип браузерной action RPG. Пиксельный монах идёт из лагеря по разбитой дороге в разрушенный монастырь. Там он гасит источник ритуала и возвращается за наградой. Движок — **Babylon.js**, сборка — **Vite**. Мир — одна непрерывная область с фиксированной изометрией 2:1. Вся земля лежит на одном уровне; объём задают персонажи и окружение. HUD компактный: каменные пиксельные рамки, пиксельные значки и читаемый системный шрифт.

[Анимационный артбук](assets/concepts/animation-bible-01/README.md) содержит 14 листов и индекс: ключевые позы монаха, трёх монстров, окружения и эффектов, ссылки Paper, оригиналы и промпты. В игру перенесены монах, гончая, стреляющий дух, панцирник и эффекты. Лагерь собран по [артборду «Панорама лагеря» в Paper](https://app.paper.design/file/01M5JE4QF1S7K7921DAQTPSHYY/p-A-0/17I-0) в игровом масштабе. Дорога и двор монастыря собраны в том же стиле: тот же камень, кипарисы, кусты, луг и утоптанная земля.

## Запуск

Нужны Node.js **22.12+** и npm. Проверено на Node.js 24.13.0.

```sh
npm ci
npm run dev
```

Открой адрес, напечатанный Vite, обычно `http://127.0.0.1:5173/`. Нужен браузер с WebGL. Управление доступно с клавиатуры и мыши или геймпада; сенсорный режим проходит интеграцию. Все шрифты и игровые ресурсы локальные; внешние сервисы не требуются. В начальной панели доступны три тона кожи, две причёски и три цвета пояса — 18 сочетаний. Старт доступен после загрузки мира и выбранного облика. При ошибке облика нажми «Повторить». Звук и музыка включаются после нажатия кнопки старта.

Если после обновления зависимостей Vite показывает устаревшие модули, перезапусти его с `npm run dev -- --force`. Не запускай второй Vite на копии проекта с общей папкой `node_modules`: он перепишет кэш `node_modules/.vite` у работающего сервера.

Проект — локальный git-репозиторий без удалённого адреса. Первый коммит `4f716ac` — снимок прототипа до этого этапа; изменения этапа ещё не закоммичены. Папка `artifacts/` указана в `.gitignore`, поэтому отчёты, логи и рабочие страницы в коммиты не попадают.

## Телефон: быстрая ссылка

Для игры по домашней Wi-Fi сети используй готовую сборку. В ней меньше запросов и кода, чем у dev-сервера. Статический сервер сжимает JS, CSS и JSON через gzip. Рисунки и звук остаются прежними.

Из корня проекта:

```sh
npm run build
node scripts/serve-dist.mjs --host 0.0.0.0 --port 5183
```

На Mac узнай адрес Wi-Fi:

```sh
ipconfig getifaddr en0
```

Если команда вернула, например, `192.168.1.20`, открой на телефоне `http://192.168.1.20:5183/`. Оба устройства должны быть в одной Wi-Fi сети. Разреши Node входящие соединения, если macOS спросит. Добавляй на домашний экран именно эту ссылку. Dev-сервер и прокси на 5173/5174 для неё не нужны. Сервер остановится по Ctrl+C.

После изменения игры снова выполни `npm run build`. Сервер читает новые файлы без перезапуска. HTML и `version.json` всегда отдаются с `Cache-Control: no-store`. Файлы с хэшем в `/assets/` кэшируются на год; новая сборка меняет их адреса. Проверка версии на странице обнаруживает новую сборку по прежним правилам.

## Обновление приложения на домашнем экране

Сборка создаёт `dist/version.json` и внедряет тот же идентификатор в HTML. Страница проверяет его без HTTP-кэша при запуске, возвращении из фона, восстановлении из BFCache и раз в 3 минуты, пока видима. На стартовом экране новая версия открывается автоматически. Незавершённый путь, включая паузу и панель «Монах», не прерывается: уведомление остаётся до конца забега. После победы или поражения нажми «Доступна новая версия — обновить». Сохранений между запусками пока нет. Service worker не используется.

Vite требует перепроверять HTML (`Cache-Control: no-cache`) и отдаёт `/version.json` с `Cache-Control: no-store`; в dev идентификатор меняется при правках `src/`, `assets/`, `public/` и `index.html`. После установки этого изменения потребуется один обычный перезапуск Vite владельцем сервера, чтобы загрузить новый плагин; прокси на 5174 продолжит использовать тот же origin и порт.

В production публикуй весь `dist/`, включая `version.json`, атомарно. На хостинге настрой `Cache-Control: no-store` для HTML и `version.json`; файлы с хэшем в `assets/` можно кэшировать надолго. Параметры `seed` и hash сохраняются при обновлении, а служебный параметр `__ritual_update` обходит старый HTML-кэш и защищает от цикла перезагрузок.

У уже установленной старой версии ещё нет этой проверки: после публикации один раз полностью закрой приложение на телефоне и открой снова. Если оно всё ещё показывает старую страницу, открой адрес в Safari/Chrome с новым параметром, например `?first-update=1`, и при необходимости пересоздай значок из этой страницы. Дальнейшие обновления обнаруживаются самой игрой; переустановка значка каждый раз не требуется.

### Геймпад

Игра читает геймпады PlayStation (DualSense, DualShock 4) и Xbox через стандартный Gamepad API браузера. Chrome и Firefox показывают геймпад странице только после первого нажатия кнопки; это нажатие уже работает. HUD, легенда паузы, подсказки панели, уведомления и пустой слот называют кнопки того устройства, которым игрок пользовался последним: например, «Create — умения» на PlayStation и «View — умения» на Xbox вместо «K — умения». Клавиша, щелчок или движение мыши возвращают надписи клавиатуры. Надписи всех устройств собраны в `controlKeys` из `src/gamepad.js`.

| Прицеливание; без правого стика прицел идёт за движением | Правый стик | Правый стик |
| Серия ударов | Удерживать R2 | Удерживать RT |
| Рывок | ✕ | A |
| Техники слотов ПКМ, Q, F | □, △, ○ | X, Y, B |
| Взаимодействие | R1 или L1 | RB или LB |
| Пауза и продолжение | Options | Menu |
| Панель «Монах»: открыть и закрыть | Create или тачпад | View |
| В панели: соседняя вкладка | L1 / R1 | LB / RB |
| В панели и меню: перевести фокус | Крестовина | Крестовина |

Мёртвая зона левого стика — 0,18, правого — 0,3. Для «Прыжка журавля» наклон правого стика задаёт дальность: от минимальной на краю мёртвой зоны до полной при полном наклоне. После отпускания стика дальность и направление берутся по самому сильному наклону за последние 6 кадров. Поэтому возврат стика к центру дальность не сокращает. Прицел по движению или по взгляду монаха бьёт на 4 единицы. Удары по врагам, урон по монаху, удачное отражение, приземление журавля, «Последний вздох», поражение и новый уровень дают вибрацию. Вибрация работает, только пока геймпад — устройство в работе и пока выключено «уменьшение движения». L2/LT, нажатия стиков и кнопка PS/Xbox не заняты. Таблица кнопок и правила — в `src/gamepad.js`.

### Телефон — интеграция

Сенсорный слой включается для грубого указателя или после первого касания. Игра рассчитана на горизонтальное окно от 568×320 CSS px. Поворот в портрет ставит игру на паузу. Проверка на настоящих телефонах ещё нужна.

| Действие | Касание |
| --- | --- |
| Движение | Плавающий джойстик слева; за мёртвой зоной — полная скорость |
| Серия ударов | Удерживать «Удар» |
| Рывок | «Шаг» |
| Техники слотов ПКМ, Q, F | Кнопки 1, 2, 3 |
| Взаимодействие | Кнопка с рукой и названием действия возле объекта |
| Панель и пауза | «Монах» и «Пауза» |

Автоприцел выбирает ближайшего врага в конусе по направлению движения, затем врага вплотную. Ладонь и Прыжок срабатывают при отпускании кнопки. Потяни палец от кнопки техники для ручного прицела. Отпусти над «Отмена», чтобы отменить прицел. Техники без прицела срабатывают сразу при касании. Правила — в `src/touch.js` и [спецификации телефона](docs/design/mobile-touch.md).

### Панель «Монах» и бой

Панель «Монах» на компьютере занимает 288×208u и помещается в окно 800×600. Пока она открыта, симуляция стоит, как в паузе, а HUD приглушён. «Персонаж» показывает уровень, опыт, характеристики и дерево «Путь монаха»; «Сбросить путь» в бою закрыт. «Снаряжение» показывает слот оружия, сумку 4×2, итог «Если надеть» и две карточки сравнения. «Умения» показывает слоты, список техник, числа, метку «Панцирник:» и модификаторы. После припасов лагеря панель сама открывается на «Снаряжении» с подсказкой «Выбери оружие». Правила — в `docs/design/skills-gear-progression.md`, разделы 5.5–5.9.

Бег — 5,4 единицы/с. Рывок идёт со скоростью 16 единиц/с в течение 0,2 с, то есть на 3,2 единицы; перезарядка — 1,2 с. Бегущий монах смотрит по направлению движения. Стоящий монах смотрит на прицел. Удар поворачивает монаха к прицелу и держит это направление до конца удара. При беге и стойке влево или вправо монах показан сбоку.

Гончая предупреждает о прыжке, дух фиксирует линию выстрела. Уходи с этой линии и сближайся после атаки. ЛКМ сама не перемещает героя к цели. Удар серии даёт 12 духа за удар независимо от числа целей. Удар, который попал только в закрытый панцирь, даёт 4 духа. Запас духа ограничен 100. Волна поражает группу вокруг монаха. Рывок наносит урон каждому задетому врагу один раз. Каждый четвёртый побеждённый монстр оставляет подбор на 18 здоровья.

**Панцирник** — третий монстр, 160 здоровья. Легенда паузы объясняет его одной строкой: «Панцирник держит удары спереди: бей в спину, рывок и волна раскалывают панцирь».

- Передний сектор ±60° блокирует удары. Заблокированный удар наносит 25% урона.
- Удары сбоку и в спину наносят полный урон. Панцирник поворачивается медленно, 2,5 рад/с.
- Рывок или волна раскалывают панцирь. Этот удар наносит полный урон. Затем панцирник лежит открытым 1,6 с.
- Повторный рывок или волна во время оглушения не продлевают его. После оглушения панцирь 1,0 с нельзя расколоть снова. В это время рывок и волна спереди тоже блокируются.
- Живой панцирник — твёрдое тело. Монах не проходит сквозь него, а скользит по краю. Рывок проходит насквозь. Отбрасывание не вдавливает панцирника в монаха.
- Перед ударом панцирник 0,8 с показывает на земле сектор замаха. Это точная зона удара: 22 урона в секторе ±60°. Сектор не заходит за стены и колонны, потому что там удар не попадает.
- На пути домой панцирник сначала разворачивается и идёт медленно. Он не скользит задом.

На боковой тропе тайник и святилище однократно восстанавливают до 25 и 40 здоровья соответственно. Победи 12 стражей двора, разбей открытый источник, вернись в лагерь и получи янтарную бусину через E. Очистка всей дороги необязательна. Между областями можно свободно ходить: координаты, ранения, враги и снаряды не сбрасываются. В лагерь монстры не заходят.

Проходимая область первого региона занимает примерно 41×104 игровые единицы. В ней 34 монстра трёх видов в шести группах: 19 гончих, 10 духов и 5 панцирников. Вся земля находится на высоте 0: уступов и приподнятых платформ нет.

Лагерь занимает 711 проходимых клеток. Костёр стоит в центре утоптанной поляны, рядом тренога с котлом и бревно. Две палатки с ящиками и мешками стоят на северо-востоке и юго-западе, ковёр с наградой — к юго-западу от огня. Дорога уходит на северо-запад между двумя разрушенными столбами. Края поляны образуют каменные массивы, кипарисы и кусты. За северо-восточным краем виден дальний горный фон. Это нарисованный задник за линией горизонта: по нему нельзя ходить, а при движении он медленно смещается.

Дорога лежит на лугу и утоптанной земле лагеря до самого шва со двором. Полоса земли извивается внутри прежней маски прохода. Вдоль краёв прохода идёт пояс из камня, кипарисов, кустов и пучков травы с меняющимся ритмом. Снаружи стоят рощи и каменные гряды. Четыре столба дороги нарисованы как разрушенные колонны. К западу от святилища стоят ворота-руина из пакета руин монастыря. Маска прохода, коллайдеры и встречи дороги не изменились.

Двор монастыря занимает 382 проходимые клетки: прямоугольник 17×20 и горло дороги. Пол — плиты, сквозь них растут трава и мох; вокруг стен лежит луг лагеря. Задние стены высокие, с окнами, проломом и обломанными концами. Передние стены — низкие парапеты, три из них разбиты, поэтому они не закрывают героя. За источником стоит свободная арка; актёр за ней или в проходе делает её полупрозрачной. Из четырёх колонн цела одна, за источником; три обломаны, чтобы не закрывать бой. Источник стоит в гнезде низкого плоского помоста 4×4 единицы. Пока печать цела, на помосте светятся магентовые руны. Магентовые жаровни стоят по бокам помоста. Источник, жаровни и святилище дороги нарисованы заново в камне руин; пламя жаровен мерцает. Коллайдер жаровен двора — радиус 0,28 по каменной ноге; жаровни дороги сохраняют 0,22.

Две боковые зоны необязательны:

```
                                 лагерь
                                   │
                                 дорога ── тропа ──► Старое кладбище (восток)
                                   │
Сад обители (запад) ◄── пролом ── двор
```

«Старое кладбище» занимает 352 клетки к востоку от дороги. Короткая тропа ведёт к его воротам между стаями road-approach и road-crossing. «Сад обители» занимает 319 клеток к западу от двора. Вход — пролом в задней стене двора. В каждой зоне две стаи и до трёх бродячих монстров, всего 9–14. Уровень монстров: кладбище 2, сад 3. На кладбище стоит реликварий, в саду — тайник садовника и святилище. Пункт зоны появляется в полосе зон под картой после первого входа. Полная зачистка с обеими зонами даёт 1300–1500 опыта и уровень 7. Основной путь и его встречи не изменились. План и числа — в `docs/design/world-expansion.md`.

Новые колонны и перенесённые жаровни изменили расстановку 12 стражей двора во многих seed, включая seed по умолчанию 20261023. Правила `encounter-layout.js` не менялись, а лагерь и дорога расставляются как раньше. Координатор принял новую расстановку: все стражи стоят на проходимом полу и достижимы. Тест закрепляет её хэшем позиций для seed 20261023, 1 и 12345.

При новом забеге позиции монстров выбираются внутри заданных областей с проверкой проходов и минимальных расстояний. Мелкая трава возле точек появления также может немного меняться: существующее правило освобождает силуэты монстров от декора; рельеф и проходы остаются прежними. Гончие сближаются с небольшим смещением, все виды мягко обходят соседей; предупреждение уже начатой атаки не сдвигается. Камера показывает на 20% больше мира по каждой оси.

Симуляция идёт шагами 1/120 с. Отрисовка смешивает два последних шага, поэтому движение ровное при любой частоте кадров. Картинка отстаёт от симуляции на один шаг, 8,3 мс. Камера и все движущиеся актёры стоят на одной решётке экранных пикселей. Под персонажами лежат пиксельные контактные тени без размытия. Предмет, который закрывает героя или монстра, становится полупрозрачным. На дороге эта проверка теперь занимает около 1,8 мс на кадр вместо 4,4 мс.

HUD устроен как в Diablo. Сфера здоровья стоит в левом нижнем углу, сфера духа — в правом. Сфера 37u заполняется рядами по 1u; числа стоят на табличке под сферой. Вдоль нижнего края между сферами идёт полоса опыта из 10 ячеек. Слева от неё стоят рамка уровня и мигающая метка «+1», пока очко пути не потрачено. По центру стоят пять слотов: ЛКМ · Пробел · ПКМ · Q · F. Слот показывает перезарядку, нехватку духа, замок «ур. N» и янтарную точку новой техники до первого применения. При здоровье меньше 35 кольцо сферы становится коралловым, пустое стекло мигает, а над сферой появляется «дыши. и продолжай.». Новый уровень показывает уведомление в две строки; уведомления идут по очереди. Над сферой духа на 3 с появляется строка добычи: имя предмета цвета редкости и разница урона в секунду с надетым оружием. Размеры и правила — в `docs/design/skills-gear-progression.md`, раздел 5.2. HUD занимает 96 px от нижнего края при `--u` = 2 px. Рамки, полосы и значки стоят на пиксельной сетке игры: одна единица `--u` равна одному пикселю мира. Текст набран системным шрифтом 13 px с весом 600; на больших экранах он растёт вместе с `--u`. Названия умений и клавиши собраны в легенде паузы. Курсоры пиксельные: прицел над полем боя, стрелка в меню и янтарная стрелка над кнопками. Курсоры растут вместе с `--u`: есть версии для 2, 3 и 4 px; при `--u` от 5 px остаётся версия 4 px. Если браузер не загрузит рисунок курсора, работает системный курсор.

Шаги монаха и голоса монстров — записанные звуки (раздел «Звуки» ниже). Остальные эффекты синтезируются через WebAudio. Шаги монаха совпадают с кадрами касания и звучат по-разному на траве, земле, камне, гравии, листве и ковре. Каждый монстр подаёт голос, когда замечает монаха, замахивается, получает удар и умирает. У трёх ударов серии разные взмахи. Попадание звучит по материалу цели: гончая, дух, панцирь, источник или закрытый щит. Лимитер на общей шине не даёт плотному бою искажаться. Фоновая музыка — шесть записанных треков в стиле тёмной кинематографичной музыки: по одному на каждую зону и боевой (раздел «Музыка» ниже). При смене зоны треки сменяются плавно. В бою боевой трек вступает поверх трека зоны, а трек зоны стихает. Пауза приглушает музыку. Ошибки звука не останавливают игру; первая из них пишется в консоль.

Звук ещё никто не слушал на слух. Для прослушивания открой `http://127.0.0.1:5173/artifacts/audio-preview.html` при запущенном `npm run dev`. Страница использует те же `GameAudio` и музыку, что игра. Звук начинается только после кнопки «Включить звук». Кнопки играют отдельные звуки и треки музыки, а таблица внизу подсказывает, какие константы менять в `src/audio.js`, `src/sfx.js`, `src/music.js`, `scripts/build-sfx.mjs` и `scripts/build-music.mjs`.

Все локации находятся под открытым небом; двор — руины без крыши. Подземелья и крипты не входят в направление игры.

При потере фокуса игра ставится на паузу. После победы или гибели можно начать заново: облик сохраняется, встречи и находки сбрасываются. Бусина — трофей забега без бонуса к характеристикам.

## Проверка и сборка

```sh
npm run build
npm test
npm run preview
```

`npm test` запускает встроенный `node:test`. Тесты проверяют бой, дух, панцирника, группы врагов, навигацию, непрерывность состояния, условия задания, анимации, боковой вид монаха, направление взгляда, интерполяцию отрисовки, пиксельную решётку, тени, маски попаданий, раскладку лагеря, дороги и двора, горный фон, освобождение объектов сцены, HUD, курсоры, выбор облика и восстановление загрузки. Звук и музыка проверяются с поддельным `AudioContext` из `tests/helpers/fake-audio-context.js`.

`npm run build` создаёт статическую сборку в `dist/`; `npm run preview` открывает её локально. `vite.config.js` делит статическую часть Babylon.js на несколько файлов, поэтому предупреждения о большом файле больше нет. Эти файлы импортируют друг друга по кругу. Первая версия деления поэтому ломала собранную игру: файл Babylon выполнялся раньше своей зависимости, и страница падала при загрузке. Dev-сервер эту ошибку не показывал. Исправление — `strictExecutionOrder: true` в `vite.config.js`; теперь собранная игра загружается. `tests/build-chunks.test.js` проверяет сборку:

1. Каждый JS-файл не больше 500 кБ.
2. `dist/index.html` ссылается только на существующие файлы.
3. Каждый файл Babylon импортируется без ошибки порядка модулей.
4. Вход сборки выполняет все файлы Babylon и останавливается только на `document is not defined`, то есть уже в коде игры.

Без папки `dist/` эти тесты пропускаются, поэтому сначала запускай `npm run build`.

## Организация кода

- `src/game.js` — детерминированная симуляция боя без DOM и WebGL. Здесь щит, пролом и замах панцирника, его возврат домой и его тело как препятствие для монаха.
- `src/overworld.js` — единая карта, глобальные координаты областей и сборка встреч. `ROAD_EARTH` задаёт извилистую полосу земли дороги; `translateZone` сдвигает раскладки двора и боковых зон в общий мир. Каждая зона несёт списки `caches` и `shrines`.
- `src/side-zones.js` — коробки боковых зон, их сдвиги, клетки перехода с дороги и двора (`SIDE_LINKS`) и маска прохода позвоночника (`SPINE_WALK`).
- `src/cemetery-layout.js`, `src/orchard-layout.js` — авторские раскладки кладбища и сада: области прохода, предметы, мощение, тайник и святилище.
- `src/zone-dressing.js` — общая расстановка предметов боковой зоны: края маски, россыпь у края и внешние рощи. Кадры берутся из атласов `pixel-v13`, руин и лагеря.
- `src/encounter-layout.js` — воспроизводимые состав и позиции шести стай по seed, а также одиночки, пары и тройки бродяг. Затем отдельным потоком ставятся четыре стаи и бродячие боковых зон. Число монстров меняется между забегами.
- `src/enemy-steering.js` — направления сближения и локальное избегание соседей.
- `src/campaign.js` — исходные локальные макеты и параметры приключения, включая `BEETLE_TIMINGS` и `BEETLE_STATS`. Двор берётся из `COURTYARD_LAYOUT`.
- `src/monk-combat.js` — общие параметры бега, ударов, духа, волны, рывка, здоровья врагов и подбора здоровья.
- `src/progression.js` — опыт, уровни, дерево «Путь монаха» и масштаб монстров.
- `src/items.js` — семейства оружия, свойства, редкости, добыча по seed и правила сумки.
- `src/skills.js` — слоты, открытия техник, модификаторы и параметры умений.
- `src/run-progress.js` — применение развития к забегу: характеристики, опыт, путь, слоты и перезарядки.
- `src/inventory-actions.js` — припасы, предметы на земле, подбор, надевание и выброс.
- `src/game-events.js` — запись событий симуляции для интерфейса, эффектов и звука.
- `src/camp-layout.js` — лагерь по артборду: перевод координат доски в мир (`fromArtboard`), контур прохода, предметы и коллайдеры, края поляны, горизонт и горный фон. Точка опоры спрайта отделена от центра коллизии.
- `src/road-country.js` — раскладка дороги в стиле лагеря: 38 авторских объектов (`ROAD_FEATURES`), пояс у краёв прохода, внешние рощи, каменные гряды и пучки травы.
- `src/courtyard-layout.js` — раскладка двора (`COURTYARD_LAYOUT`): маска прохода, стены, арка, колонны, помост, обломки, контур плит и луг вокруг.
- `src/world.js` — препятствия, столкновения и поиск пути в переданной локации.
- `src/appearance.js` — допустимые варианты внешности и URL атласов и превью. Атласы обликов берутся из `pixel-v10/monk-side`, превью — из `pixel-v3/appearance`.
- `src/render.js` — камера, сцена, эффекты, карта. Камера и актёры стоят на одной решётке экранных пикселей. Здесь же рисуются сектор замаха панцирника с учётом стен, источник ритуала из атласа руин и сенсорный прицел (`drawTouchView`).
- `src/render-interpolation.js` — `MotionHistory`: позиции тел перед шагом симуляции и смешанная позиция для отрисовки.
- `src/pixel-scene.js` — загрузка атласов, спрайты, декорации и пиксельные контактные тени. Здесь рисуются предметы всех авторских зон, плоские кадры на земле, руны помоста и печать.
- `src/landscape.js`, `src/country-*.js` — плоский грунт, смешение поверхностей, природные границы и мелкие детали; `world.tiles` задаёт область движения, `world.paving` — рисунок тропы. `src/country-terrain.js` также рисует край поляны, луг и землю лагеря на дороге, плиты двора, швы между зонами и горы за горизонтом. Процедурные рощи и камни `pixel-v4` ставятся только вне авторских зон.
- `src/pixel-animation.js` — выбор кадров и направлений по состоянию симуляции. Гистерезис направления — 15°, шаг бега — 0,56 единицы на кадр. Боковой рисунок включается для курса в пределах ±20° от горизонтали экрана.
- `src/pixel-assets.js` — метаданные ресурсов.
- `src/pixel-picking.js` — попадания по прозрачному силуэту и проверка перекрытия. Непрозрачная рамка каждого кадра считается один раз, поэтому проверка смотрит только туда.
- `src/input.js` — клавиатура и мышь. C, I, K и Tab ставят в очередь открытие панели «Монах».
- `src/key-codes.js` — физические клавиши и запасное распознавание по букве или `keyCode`.
- `src/gamepad.js` — геймпады PlayStation и Xbox без DOM и движка. `GamepadInput.poll()` раз в кадр читает геймпад и возвращает нажатия кадра, включая паузу, панель и навигацию меню. `sample()` добавляет геймпад к выборке клавиатуры. Здесь же семейство геймпада по `id`, значки кнопок, мёртвые зоны и вибрация по событиям кадра.
- `src/touch.js` — сенсорный ввод без DOM: пальцы, джойстик, автоприцел и ручной прицел техник.
- `src/touch-ui.js`, `src/mobile.css` — сенсорные кнопки, HUD, безопасные отступы, поворот, полный экран и системный «назад». Интеграция телефона ещё проходит проверку.
- `src/monk-panel.js` — панель «Монах». `PanelController` хранит вкладку, наведение, выбор и метки «новое» и вызывает правила из `run-progress.js` и `inventory-actions.js`; DOM ему не нужен, поэтому тесты управляют им напрямую. `MonkPanel` рисует вкладки в `#monk-panel` и передаёт ему мышь и клавиши. Значки берутся из `assets/ui/pixel-v5/icons`: файл выбирается по `--u` × масштаб рисунка × `devicePixelRatio`.
- `src/audio.js` — звуковые эффекты: синтез ударов по материалу цели, поверхность под шагом, голоса монстров по событиям, лимиты голосов, объединение событий кадра и лимитер. При первом включении звука файл создаёт музыку и банк записанных звуков.
- `src/sfx.js` — записанные звуки: шаги монаха и голоса монстров, их уровни, ленивая загрузка и выбор варианта.
- `src/music.js` — фоновая музыка: шесть записанных треков (пять зон и бой), ленивая загрузка, кроссфейд зон и боевой трек поверх трека зоны.
- `src/main.js`, `src/styles.css`, `index.html` — игровой цикл и интерфейс. `main.js` передаёт отрисовке долю шага для интерполяции и вызывает звук через `guardAudio`.
- `vite.config.js` — только деление сборки на файлы и строгий порядок их выполнения (`strictExecutionOrder`).
- `tests/*.test.js` — тесты правил, отрисовки, звука, сборки и интеграции проекции камеры; `tests/helpers/` — общие подделки для тестов.

## Границы прототипа

Это короткое приключение в одной постоянной области: шесть стай и бродяги трёх видов, необязательная боковая тропа и одно задание с возвращением. Это первый регион, без бесконечного мира или потоковой загрузки. Есть сумка, добыча по seed, оружие, уровни, путь и техники. Сенсорное управление проходит интеграцию. Постоянных сохранений нет: обновление страницы начинает новый забег. Состояние этапа и проверки — в [передаче RPG-систем](artifacts/systems-stage-handoff.md). Новые ассеты должны следовать [визуальному направлению](docs/art-direction.md).

Известные ограничения:

- Маска прохода дороги под рисунком осталась прямоугольной. Пояс у краёв её скрывает, но длинные прямые участки ещё угадываются. Изменение маски изменило бы встречи.
- Плиты двора повторяются каждые 4 единицы. Наклейки с трещинами, мхом и крошкой разбивают повтор, но на открытой мостовой он заметен.
- Пламя жаровен нарисовано программно. Оно проще рисованного пламени `pixel-v2`.
- Графика лагеря проще артборда. Камни и горы нарисованы программно. Край поляны немного «шумит» из-за пиксельного дизеринга.
- Боковой вид есть только у бега и стойки монаха. Верх тела в нём — прежний рисунок с торсом, повёрнутым к камере на 3/4. Удары, рывок, волна, урон и смерть показывают четыре диагональных направления.
- Вверх и вниз по экрану у актёров нет своего ракурса: там видна диагональная поза. На диагоналях и при беге вверх и вниз стопа монаха ещё немного скользит.
- Интерполяция добавляет одну задержку шага, 8,3 мс. Эффекты в точке события стоят там, где монах находится в симуляции, то есть до 1,2 px впереди нарисованного монаха.
- При 2560×1080 HUD не уменьшается, потому что `--u` следует масштабу мира 3×.
- У панцирника один нарисованный задний ракурс; задние клипы собраны из него. Подробности — в [отчёте по графике](artifacts/beetle-art.md).
- Звук и музыку никто ещё не слушал на слух. Уровни измерены только офлайн-рендером в `OfflineAudioContext`. Для прослушивания есть `/artifacts/audio-preview.html`.
- Планы в Paper (`p-B-0`, `p-C-0`) показывают прежние раскладки.
- Другие браузеры, Windows и слабые GPU отдельно не тестировались.

Баланс и продолжительность первого прохождения ещё требуют игровых итераций. Бот маршрута не обходит панцирника и не уклоняется намеренно. Его прогоны — техническая проверка доступности и состояния задания, а не время обычной первой игры.

## Музыка

Фоновая музыка — шесть записанных треков: по одному на каждую зону и один боевой. Треки сгенерированы через ElevenLabs Music API (модель `music_v2_5`, только инструментал). Стиль — тёмная кинематографичная музыка: оркестр, синтезаторы, низкие струнные, хор без слов. Все треки в ре миноре, поэтому смена зоны не даёт диссонанса.

| Файл | Зона | Настроение | Петля |
|---|---|---|---|
| `music-camp.m4a` | лагерь | спокойный тёплый отдых | 72,7 с |
| `music-road.m4a` | дорога | странствие, тревога | 96,0 с |
| `music-courtyard.m4a` | двор монастыря | ритуал, хор, угроза | 87,8 с |
| `music-cemetery.m4a` | кладбище | холод, пустота, жуть | 90,5 с |
| `music-orchard.m4a` | сад | меланхолия, увядшая красота | 85,0 с |
| `music-combat.m4a` | бой | ударные, низкая медь, остинато струнных | 66,5 с |

Файлы лежат в `assets/game/music/`: AAC 128 кбит/с, 48 кГц, стерео, не больше 1,6 МБ. Каждый файл — готовая петля. Её начало — равномощный кроссфейд от хвоста трека к его началу. До и после петли стоит по 0,1 с копии, поэтому шов не слышен, даже если декодер оставил задержку AAC.

Как играет музыка (`src/music.js`):

1. Загрузка начинается с первого кадра после «Начать путь». Прелоадер (`src/boot-splash.js`) музыку не грузит.
2. Сначала грузится трек текущей зоны, потом боевой трек, потом остальные. Одновременно идёт одна загрузка.
3. В `AudioBuffer` декодируются только трек зоны, боевой трек и трек, который ещё затихает. Декодированы не больше двух треков зон сразу. Телефон декодирует с частотой 32 кГц, около 256 КБ на секунду стерео.
4. `AudioBufferSourceNode` повторяет петлю между `loopStart` и `loopEnd` без зазора.
5. Смена зоны — равномощный кроссфейд за 2,5 с. Трек зоны продолжает с того места, где остановился.
6. В бою боевой трек вступает за 1,2 с, а трек зоны стихает до 30 %. После боя боевой трек держится 3 с и затихает за 3 с.
7. Пауза приглушает музыку до 35 %. Кнопка звука выключает всё через общий мастер.
8. Трек молчит, пока его файл не загружен. Если файл не загрузился или не декодировался, трек молчит, а игра идёт дальше без ошибок.

Как сделать треки заново (`scripts/build-music.mjs`, нужны Node и ffmpeg с кодеком AudioToolbox на macOS):

1. Задай ключ в переменной окружения `ELEVENLABS_API_KEY`. Не записывай ключ в файлы.
2. Сгенерируй треки во временную папку: `node scripts/build-music.mjs generate /tmp/music`. Один трек: добавь его имя в конец команды. Генерация тратит около 12,5 кредита на секунду музыки, все шесть треков — около 7 500 кредитов.
3. Сделай петли: `node scripts/build-music.mjs loop /tmp/music`. Этот шаг бесплатный и работает офлайн.
4. Скопируй `/tmp/music/out/music-*.m4a` в `assets/game/music/`.
5. Перенеси `loopSeconds` из `/tmp/music/out/loops.json` в `TRACKS` в `src/music.js`.
6. Запусти `node --test --test-concurrency=1 tests/audio-music.test.js`.

Промпты лежат в `scripts/build-music.mjs`. Чтобы сгенерировать трек ещё раз, удали его файл в `raw/`. Музыку никто ещё не слушал на слух: шов петли проверен только измерениями.

## Звуки

Шаги монаха и голоса монстров — записанные звуки. Они сгенерированы через ElevenLabs Sound Effects API (модель `eleven_text_to_sound_v3`). Стиль — реалистичное тёмное фэнтези в тон музыке. Остальные эффекты синтезируются в `src/audio.js`: взмахи, попадания, умения, добыча, интерфейс и шаги монстров.

| Файлы | Когда звучат | Вариантов |
|---|---|---|
| `step-grass`, `step-earth`, `step-stone` | шаг монаха по траве, утоптанной земле, камню | по 5 |
| `step-gravel`, `step-leaves`, `step-rug` | шаг монаха по гравию и щебню, по опавшей листве, по ковру в лагере | по 5 |
| `hound-notice`, `wraith-notice`, `beetle-notice` | монстр замечает монаха (событие `alert`) | по 2 |
| `hound-attack`, `wraith-attack`, `beetle-attack` | монстр замахивается (событие `windup`) | по 3 |
| `hound-hurt`, `wraith-hurt`, `beetle-hurt` | монстр получает удар и не умирает в этом кадре | по 3 |
| `hound-death`, `wraith-death`, `beetle-death` | монстр умирает | по 2 |

`hound` — гончая, `wraith` — дух, `beetle` — панцирник. Файлы лежат в `assets/game/sfx/`: 60 файлов AAC 80 кбит/с, 48 кГц, моно, всего около 0,5 МБ. Шаг длится до 0,38 с, голос — от 0,5 до 2 с.

Как играют звуки (`src/sfx.js` и `src/audio.js`):

1. Загрузка начинается с первого кадра после «Начать путь». Прелоадер (`src/boot-splash.js`) звуки не грузит.
2. Сначала грузятся шаги, потом голоса. Одновременно идут три загрузки.
3. Каждый файл декодируется один раз и остаётся в памяти. Телефон декодирует с частотой 32 кГц: около 5,3 МБ на все звуки. Компьютер при 48 кГц держит около 7,9 МБ.
4. Звук берёт случайный вариант, но не тот, что звучал последним.
5. Поверхность шага берётся из наземного рисунка под ногой: ковёр, гравий, щебень, листва, плиты, мох, могильная земля. Вне рисунков она берётся из маски земли.
6. Голос монстра стихает с расстоянием, как шаги монстров, и молчит дальше 16 единиц. Один голос одного вида монстров не повторяется раньше паузы: «замечает» — 1,2 с, «атака» — 0,3 с, «ранен» — 0,35 с, «смерть» — 0,15 с. Крик «ранен» звучит на 30 мс позже удара, поэтому удар слышен первым.
7. Голоса делят общий лимит голосов. Компьютер играет голос, пока звучит меньше 24 слоёв из 32. Телефон играет голос, пока звучит меньше 8 слоёв из 12. Удары важнее голосов, голоса важнее шагов.
8. Пока файл не загружен, его вариант молчит. Если файл не загрузился или не декодировался, вариант молчит, а игра идёт без ошибок.

Как сделать звуки заново (`scripts/build-sfx.mjs`, нужны Node и ffmpeg с кодеком AudioToolbox на macOS):

1. Задай ключ в переменной окружения `ELEVENLABS_API_KEY`. Не записывай ключ в файлы.
2. Сгенерируй звуки во временную папку: `node scripts/build-sfx.mjs generate /tmp/sfx`. Один звук: добавь его имя в конец команды, например `step-grass`. По счётчику в октябре 2026 генерация стоила около 10 кредитов на секунду звука, все 60 файлов — около 490 кредитов.
3. Обработай файлы: `node scripts/build-sfx.mjs process /tmp/sfx`. Этот шаг режет тишину, выравнивает громкость и кодирует AAC. Он бесплатный и работает офлайн.
4. Скопируй `/tmp/sfx/out/*.m4a` в `assets/game/sfx/`.
5. Запусти `node --test --test-concurrency=1 tests/audio-sfx.test.js tests/audio.test.js tests/audio-perf.test.js`.

Промпты лежат в `scripts/build-sfx.mjs`. Чтобы сгенерировать файл ещё раз, удали его в `raw/`. Уровни звуков на шине — в `SOUNDS` в `src/sfx.js`. Звуки никто ещё не слушал на слух: уровни подобраны по измерениям громкости.
